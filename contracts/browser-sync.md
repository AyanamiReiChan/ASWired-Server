# Browser memory cache protocol

`GET /api/state/sync` returns the authenticated workspace without task/audit history or duplicate settings. Collection rows are keyed by ID, with a separate `order` map; pending task count is included. The original `/api/state` is unchanged. Task summaries are requested from the admin-only `/api/operations/tasks?limit=200`; individual results stay on the existing authorized task-detail endpoint. Audit file history remains page-local.

`GET /api/traffic?...&sync=1` uses the controller's persisted traffic ledger only. It never asks an Agent for history. Series, server totals and member totals are keyed by ID for incremental transfer, including corrections to older buckets, deletion and rolling expiry. `GET /api/servers/{id}/xray-cache?sync=1` uses the same protocol, so unchanged configuration content is not downloaded again. Calls without `sync=1` retain existing behavior.

Initial or expired baselines receive `{cursor, reset:true, data}`. Subsequent GET requests send the last cursor and receive `{cursor, base, changes, removed}`. Object changes are recursive; arrays/scalars replace their prior values; removed paths explicitly delete keys and are distinct from JSON null. The browser checks `base`, applies deletions/changes atomically, and retries without a cursor once if its baseline is missing. Server restarts/eviction cause a full reset. Baselines are scoped to user ID, current role, endpoint and query; each request is independently authorized. A cursor grants no access to another user's snapshot.

Server baselines expire after 15 minutes and are bounded to 64 entries/16 MiB serialized bytes; browser memory is also bounded and cleared on logout/account or role changes. Responses use private/no-store: the application owns this memory cache, not a shared HTTP cache. Credentials are not added to localStorage. Static data is transmitted on changes, while the browser checks workspace differences every five seconds. This saves network transfer, but still computes authorized projections on the controller; it is not a database-query optimization.

Daily summaries load on the overview/traffic pages, refreshing at 60 seconds; minute history loads only on the traffic page, at 30 seconds. Existing buckets stay visible while refreshing; late responses cannot repopulate a logged-out or changed account. Task/certificate pages request task summaries on demand. Xray configuration windows pause polling when hidden and refresh on visibility return. Save/action/delete refreshes wait for an older in-flight workspace request before obtaining fresh redacted state.
